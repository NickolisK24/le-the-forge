# R2 Contract Test Plan (R2-14)

**Status: design only.** These tests define "R2 done". Each test names the package that introduces it (R2_IMPLEMENTATION_PACKAGES.json). Package R2-P17 builds the harness and fixtures first, so the tests exist before the code they gate.

## Fixtures

| Fixture | Built from | Location | Refresh |
| --- | --- | --- | --- |
| `golden/1.4.6/` | R1 canonical outputs at last-epoch-data `0111f1e`: `affixes.json`, `passive_trees.json`, `skill_trees.json`, `weaver_tree.json`, `property_definitions.json`, plus the 1.4.6 legacy `classes.json` masteries for mastery-order tests only | `backend/tests/fixtures/canonical/1.4.6/`, a slice (see below) plus hashes of the full files | Regenerated by `scripts/build_r2_fixtures.py` from a pinned commit; never hand-edited |
| `golden/<certified 1.5>/` | The certified 1.5 bundle | same layout | Added when the operator run certifies; the switch packages require it |
| `synthetic/` | Hand-built minimal manifests that exercise every loader rejection L1–L11 | `backend/tests/fixtures/canonical/synthetic/` | Code-reviewed |
| `legacy_builds/` | Anonymised real build rows (passive raw ints, skill names, gear affix names), including the ambiguous-name cases | `backend/tests/fixtures/builds/` | Captured once before migration |

Slices keep the repository small. Fixtures hold whole records only, never trimmed fields:
- all 5 passive trees;
- 10 skill trees, chosen to include multi-prerequisite nodes, tree-less variants (Anomaly, Cinder Strike), the shifted-field nodes and a DEFECTIVE tree;
- 60 affixes, chosen to include multi-property, secondary-roll (REL-7), class-specific (REL-23) and duplicate-name cases;
- every property-definitions family.

## Test catalogue

| ID | Property proved | Method | Package |
| --- | --- | --- | --- |
| **T1 No field loss** | Every field of every canonical record reaches the Forge typed model or is listed in that adapter's `DECLARED_DROPS` with a reason | Walk the canonical JSON paths of each fixture record and assert each is mapped or declared dropped. Mirrors R1 field survival, consumer side. | P17 (harness), each family package |
| **T2 No undeclared value transformation** | Adapter output equals canonical input for every carried field, except fields listed in `DECLARED_DERIVATIONS` (each with a pure function and its own test) | Property test over fixtures. Specifically asserts **no ×100**: canonical affix T1 Added Health 5–15 is served as 5–15 (EXT-2, LOSS-1). | P05, P07, P08, P11 |
| **T3 Identity stability** | Ids are source ids. Ids are unique per family. Formatting and parsing round-trips. Re-loading the same bundle yields identical ids. No id is derived from names or positions. | Unit tests for typed ids. Uniqueness assertions: affix 1,112 unique; `(tree_id, node_id)` unique. Static check (T11) for name-keyed dicts. | P03 |
| **T4 Relationship integrity** | Every RESOLVED edge's target exists in the dataset; every unresolved edge is reported with its resolution; required relationships are resolved or the family is not TRUSTED | Graph checks over fixtures. The 1.4.6 passive trees must report their 16 IMPLAUSIBLE and 3 UNRESOLVED edges explicitly. | P07, P08, P11 |
| **T5 Mastery migration** | All 15 masteries plus 5 base classes map by `(class_id, mastery_index)` | See R2_RELATIONSHIP_MODEL.md T5-M (5 assertions × 20 entries). Golden diff lists the 190 corrected nodes. | P06 |
| **T6 Patch consistency** | The loader rejects mixed patch, mixed snapshot, hash mismatch, wrong schema and missing provenance | One synthetic manifest per rejection L1–L11; each asserts the exact error and that nothing is served | P02 |
| **T7 Trust propagation** | `consumer_state` and reasons from `TRUST_MANIFEST.json` appear unchanged in the store, in every API payload's `trust` block and in calculation outputs. QUARANTINED is never served as TRUSTED. UNKNOWN/UNSUPPORTED are never served. | Fixture manifests with each trust state; API contract tests | P02, P09 |
| **T8 Frontend/backend parity** | The frontend artifact's `data_version`, content hash, node/edge sets, mastery grouping, affix ids and ranges equal the backend store's | A CI job builds the frontend artifact and compares it with an API dump from the same bundle. Any difference fails. | P10 |
| **T9 DB provenance** | The server stamps `data_version`; client-supplied version fields are ignored. Legacy rows become `LEGACY_UNKNOWN` without fabricated versions. Updates re-stamp. A build cannot mix datasets. | Migration test on a Postgres container with `legacy_builds` fixtures; API tests posting forged `patch_version` / `data_version` | P13 |
| **T10 No fallback masking** | Missing canonical data yields an explicit error or unsupported state, never `0`, `"Unknown"`, `[]`, first match or default class | One test per DANGEROUS fallback in R2_FALLBACK_AUDIT.md: delete the record from a fixture, call the path, assert the explicit state. A lint gate blocks new dangerous patterns in data paths. | P16 (and each family package for its own paths) |
| **T11 No legacy-data fallback / foreign source** | No runtime module reads `data/` legacy files, `exports_json`, frontend copies or hand-authored game-fact constants once its family is migrated | Static import/path scan with an allowlist that shrinks per package. A runtime guard in `CanonicalDataStore` refuses registration from other paths (`FOREIGN_SOURCE`). | P02, P18 |
| **T12 Deterministic initialization** | Empty DB, then `flask db upgrade`, then start gives an identical served dataset and `datasets` row. Two starts give identical manifests and hashes. Migrations upgrade from base to head on Postgres, and reversible ones downgrade. | CI Postgres job (DB-5); startup test that hashes the served registries | P14, P15 |
| **T13 Fail closed at deploy** | A rejected bundle makes `/api/health` fail and game-data endpoints return 503 | Integration test with a corrupted bundle | P02, P14 |
| **T14 Import mapping honesty** (shape only; R4 fills it) | External ids map through `external_id_map/<provider>/<data_version>.json`; unmapped ids are reported, never index-guessed (IMP-4) | Unit test of the map loader with a fixture map | P11 |

## CI wiring

| Job | Runs | Blocks merge |
| --- | --- | --- |
| `r2-contract` | T1–T8, T10, T11 on `golden/1.4.6` and synthetic fixtures (and the certified 1.5 fixtures once present) | Yes |
| `r2-db` | T9, T12 on a Postgres service container | Yes |

| `r2-bundle-verify` | L1–L11 on the committed `data/canonical/CURRENT` bundle | Yes; also run at startup |

The existing CI gaps these close: CI never runs `db upgrade`, never runs vitest, and has no data/DB parity, trust or generated-file freshness checks (C_persistence §8).
